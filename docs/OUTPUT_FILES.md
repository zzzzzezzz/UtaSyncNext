# 输出文件说明

`output/<任务名>/subtitles/` 里同时放着字幕成品、续跑缓存和人工复核记录。它们用途不同，所以一次任务完成后看到多份文件是正常的；并不是每一份都需要交给播放器。

## 截图中的九类文件

| 文件 | 作用 | 是否影响播放 | 可以删除吗 |
| --- | --- | --- | --- |
| `<任务名>_极致打轴.srt` | Faster-Whisper 生成的原文字幕和时间轴，是翻译、花字和人工校对的源文件。 | 不直接作为最终译文，但播放器可以播放。 | 可以，但之后通常不能复用打轴结果；再次运行可能重新听写。建议保留。 |
| `<任务名>_极致打轴_双语字幕.srt` | 翻译后的普通 SRT，适合播放器外挂字幕、校对和继续导出。 | 是，属于主要成品。 | 删除会失去双语成品；保留原文和翻译缓存时，之后可以尝试重建。建议保留。 |
| `<任务名>_极致打轴_双语字幕_顶级特效.ass` | 带字体、颜色、位置和花字样式的 ASS 字幕；硬字幕压制也使用它。 | 是，属于样式成品。 | 如果不需要花字或已经完成压制，可以删除；以后可从 SRT 重新生成。 |
| `<任务名>_打轴指纹.hash` | 记录媒体、模型、声学模式和打轴规则的身份，用来判断原文 SRT 是否可以直接复用。 | 否。 | 可以，但下次会失去打轴缓存命中，可能重新听写。 |
| `<任务名>_翻译指纹.hash` | 记录一次完整翻译所对应的媒体、原文、歌词、模型和布局设置。 | 否。 | 可以；下次会重新校验翻译完成状态。翻译批次缓存还在时，通常不会重复请求已完成批次。 |
| `<任务名>_极致打轴_翻译缓存.json` | 按批次保存翻译结果，支持翻译中断后续跑，并避免重复支付 API 请求。 | 否。 | 可以，但以后重翻可能重新请求全部批次。确认不再修改前建议保留。 |

| `<任务名>_极致打轴_识别诊断.json` | 记录低置信度、重复文本、疑似幻觉和制作名单等人工复听候选。 | 否。 | 可以；缺失时系统可根据现有 SRT 重新生成基础诊断，但会丢失原始识别证据和历史记录。 |

## 按使用场景保留

### 只想拿字幕播放

保留 `<任务名>_极致打轴_双语字幕.srt`。如果播放器或压制流程需要样式，再保留对应的 `.ass`。如果还想以后重新翻译、校对或换花字，连同原文 SRT 一起保留。

### 还会继续修改这个项目

建议保留原文 SRT、双语 SRT、ASS、两个 `.hash` 和翻译缓存。它们占用空间很小，却能避免重新听写和重复调用翻译接口。

### 只准备分享成品或提交仓库

通常只导出双语 SRT、ASS 和已经压制好的视频。`api_trace.json`、诊断 JSON、翻译缓存、hash、音频缓存和运行日志都属于本地运行产物，不要提交到公开仓库；其中缓存和诊断文件还可能包含字幕内容、绝对路径或服务元数据。

歌词检查通过后，`歌词缺轴候选.json` 仍然可以删除；正式字幕不会因为删除它而改变。ASS 也不会因为删除原文 SRT 而自动更新，已经满意的样式成品可以独立保存。

## 文件为什么会一起出现

Next 把一次任务拆成打轴、翻译、排版和复核几个阶段。每个阶段分别保存可恢复的状态：打轴指纹避免重复 ASR，翻译缓存避免重复 API 请求，诊断文件保留人工复听依据，ASS 和 SRT 则是不同播放器/发布方式的成品。这样任务中途失败或换电脑设置后，可以从最后一个有效阶段继续。
